# Glossary - Web Application Security & Burp Suite

## Overview

This glossary provides concise definitions for essential web security concepts, HTTP protocol terms, vulnerability categories, and Burp Suite tools referenced throughout these practice labs.

---

## Terms & Definitions

### A
* **Access Control**: Security mechanisms that regulate which users or processes are granted access to specific resources or operations.
* **Active Directory (AD)**: Microsoft directory service used in enterprise networks to manage users, endpoints, security policies, and domain resources.
* **Authentication (AuthN)**: The process of verifying the identity of a user, device, or system (e.g., username/password, OTP, certificate).
* **Authorization (AuthZ)**: The process of determining whether an authenticated entity has permission to perform a specific action or access a resource.

### B
* **Broken Access Control**: A security flaw where an application fails to properly enforce user privileges, allowing unauthorized users to view, modify, or delete sensitive data.
* **Burp CA Certificate**: A custom root certificate generated by Burp Suite to perform TLS interception (Man-in-the-Middle) on HTTPS traffic without browser security warnings.
* **Burp Suite**: An integrated platform of tools designed for web application security auditing, vulnerability assessment, and penetration testing.

### C
* **Cookie**: A small piece of data sent by a web server and stored in the user's browser, commonly used for session management, tracking, and user preferences.
* **Cross-Origin Resource Sharing (CORS)**: A browser feature using HTTP headers to permit or restrict resource sharing between different origins.
* **Cross-Site Scripting (XSS)**: A vulnerability allowing attackers to inject malicious client-side scripts into web pages viewed by other users.
* **Cross-Site Request Forgery (CSRF)**: An attack that tricks an authenticated user's browser into sending unauthorized requests to a vulnerable web application.

### D
* **Decoder (Burp Tool)**: A utility in Burp Suite for transforming, encoding, decoding, and hashing data (e.g., URL encoding, Base64, HTML encoding, Hex, MD5, SHA-256).
* **Domain Name System (DNS)**: The hierarchical system that resolves human-readable domain names (e.g., `example.com`) into numerical IP addresses.

### H
* **HTTP (Hypertext Transfer Protocol)**: An application-layer protocol used for transmitting hypermedia documents across the web.
* **HTTP Header**: Key-value metadata fields sent in HTTP requests and responses to pass configuration details, cookies, host information, and security policies.
* **HTTP Method**: Standard request actions indicating the desired operation to be performed on a resource (`GET`, `POST`, `PUT`, `DELETE`, `PATCH`, `OPTIONS`, `HEAD`).
* **HttpOnly Flag**: A cookie attribute that prevents client-side scripts (JavaScript) from accessing the cookie, mitigating session theft via XSS attacks.

### I
* **Insecure Direct Object Reference (IDOR)**: A vulnerability occurring when an application uses user-supplied input to access objects directly without proper authorization checks.
* **Intercepting Proxy**: Software positioned between a client browser and target server that intercepts network traffic for inspection, modification, or logging.
* **Intruder (Burp Tool)**: An automated tool in Burp Suite designed to perform customized attacks (brute-forcing passwords, directory enumeration, fuzzing payloads).

### M
* **Man-in-the-Middle (MitM)**: An attack or testing scenario where an entity secretly intercepts and potentially alters communication between two parties.
* **Match and Replace**: A feature in Burp Proxy that automatically modifies headers or request parameters matching defined rules on the fly.

### O
* **OWASP Top 10**: A regularly updated awareness document published by the Open Web Application Security Project listing the top 10 most critical web application security risks.

### P
* **Parameter Tampering**: Modifying parameters passed between client and server (in URLs, form bodies, or headers) to bypass logic controls or manipulate application state.

### R
* **Repeater (Burp Tool)**: A manual request manipulation tool in Burp Suite used to modify, re-send, and analyze individual HTTP/HTTPS requests interactively.

### S
* **Same-Origin Policy (SOP)**: A core browser security model restricting how scripts from one origin interact with resources from a different origin.
* **SameSite Flag**: A cookie attribute (`Strict`, `Lax`, `None`) that controls whether cookies are sent with cross-site requests, protecting against CSRF attacks.
* **Secure Flag**: A cookie attribute ensuring that the cookie is transmitted only over encrypted (HTTPS) connections.
* **SQL Injection (SQLi)**: A vulnerability enabling attackers to interfere with database queries, allowing them to view, modify, or delete database data.

### T
* **Target Scope**: A configuration setting in Burp Suite defining which target URLs are relevant to the test, filtering out unintended background traffic.
* **Transport Layer Security (TLS)**: A cryptographic protocol designed to provide privacy and data integrity between communicating applications over HTTPS.

### U
* **User-Agent**: An HTTP header string identifying the client software, operating system, vendor, or browser requesting data from a server.
